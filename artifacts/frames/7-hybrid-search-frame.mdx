## Problem

Current search in roxabi-memory is BM25-only (`fts.py` via FTS5). Users cannot find entries that are conceptually similar but use different words — e.g. searching "machine learning" won't surface an entry about "neural networks". Adding vector similarity alongside BM25 provides semantic recall while preserving exact-match precision.

The `embedding BLOB` column already exists in schema v2 (migration 2) and the `[embeddings]` optional dependency group (`fastembed>=0.4`, `sqlite-vec>=0.1`) is declared in `pyproject.toml`, but no embedding or hybrid search code exists yet.

## Who

- **Primary:** Lyra agents and any asyncio consumer of `AsyncMemoryDB.search()`
- **Secondary:** CLI users (`rmem`) who benefit from better search results

## Constraints

- **No PyTorch** — fastembed ONNX only (~100MB model). Must not bloat the install.
- **asyncio-safe** — embedding calls via `run_in_executor`; never block the event loop.
- **Backward-compatible** — rows with `embedding IS NULL` must participate in BM25 results, be excluded from cosine scoring, and never crash.
- **Builds on schema v2** — `embedding BLOB` column and FTS5 triggers already exist. No schema changes needed.
- **sqlite-vec** — float32 blob storage + cosine similarity. No external vector DB.

## Out of Scope

- Model fine-tuning or custom training
- Multi-model support (single fastembed model only)
- GPU acceleration
- Search result UI / CLI search enhancements
- Batch import / bulk embedding migration CLI command

## Complexity

**Tier: F-lite** — Clear scope within the search domain. ~3-4 new/modified files, single domain (search + embeddings), no architectural changes. Existing schema and dependency declarations reduce unknowns.
