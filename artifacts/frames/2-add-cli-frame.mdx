## Problem

roxabi-memory is currently a library-only package with no command-line interface. Developers who need to inspect, debug, or administer memory databases must write Python scripts — even for simple tasks like listing entries or checking DB stats. This slows down troubleshooting and makes the tool less accessible for quick ad-hoc operations.

Both voiceCLI and imageCLI already ship CLIs. roxabi-memory should follow the same pattern for consistency across the Roxabi ecosystem.

## Who

- **Primary:** Developers using roxabi-memory for vault troubleshooting, data inspection, and admin tasks
- **Secondary:** Lyra agent operators who need quick terminal access to memory databases

## Constraints

- Framework: Typer (consistent with voiceCLI/imageCLI)
- Add `typer[all]` to project dependencies
- Entry point via `[project.scripts]`: `rmem = "roxabi_memory.cli:app"`
- Build system: hatchling + uv (existing)
- Must work with the existing sync `MemoryDB` API (CLI commands are synchronous)

## Out of Scope

- Embedding/vector-related CLI commands (fastembed, sqlite-vec) — future issue
- Interactive REPL mode
- Config file support (e.g., default DB path via config)
- Async CLI commands

## Complexity

**Tier: F-lite** — Clear scope, single domain (CLI layer over existing library API), no architectural decisions needed.

- Single new module (`roxabi_memory/cli.py`) + entry point registration
- ~7 commands wrapping existing `MemoryDB` methods: list, search, get, put, delete, stats, export
- No new dependencies beyond Typer
- No cross-domain impact
